> 这份规格要能单独交给另一个 agent：不依赖对话记录，也不依赖 `.lodestar/`。

## 1. 背景与目的

Orbit 第一版是给作者本人用的命令行工具（DEC-20261023-3）。每次对比结束后，作者需要把结果存成可读、可分享的文档，
否则对比结论只留在终端里，第二天就找不到了。

## 2. 范围

- 要做: `orbit export <对比编号>` 命令，把一次对比导出为一个 Markdown 文件。
- 不做: 图形界面、批量导出、PDF 或 HTML 格式、上传到任何服务。

## 3. 术语

- 对比 (Comparison): 同一输入在多个模型上的一组输出及其评分。
- 盲评 (Blind review): 打分时隐藏模型名称的评估方式；导出时要显示真实模型名。

## 4. 场景

- S1 假如本地存在编号为 42 的对比，当运行 `orbit export 42`，那么当前目录生成 `orbit-42.md`。
- S2 假如编号不存在，当运行 `orbit export 99`，那么命令以非零状态退出并提示可用编号。

## 5. 需求

- R1 报告包含：输入提示词、每个模型的名称与完整输出、每个输出的盲评分和本人评分、导出时间。
- R2 输出按本人评分从高到低排列。
- R3 文件写在当前目录，已存在同名文件时不覆盖，改用 `orbit-42-2.md` 这样的后缀。

## 6. 验收标准

- A1 (R1) 对一个含 3 个模型输出的对比运行导出，文件中出现 3 个二级标题，每个下面有输出全文和两种评分。
- A2 (R2) 评分为 3、5、4 的输出，在文件中的顺序是 5、4、3。
- A3 (R3) 连续导出两次同一对比，得到 `orbit-42.md` 和 `orbit-42-2.md`，第一个文件内容不变。

## 7. 约束与已定决策

- DEC-20261023-3: 第一版只做 CLI，不做图形界面。
- 数据只写本地文件，导出过程不访问网络；报告中不得包含 API key。

## 8. 影响范围

- 上下文 / 模块 / 文件: 新增 export 子命令；读取现有的对比存储。
- 接口与数据: 不改变对比的存储格式。
